# M5 report: the desktop app

Issue 9, branch `m5-desktop`. Spec: `docs/specs/05-desktop.md`. Decisions: D-91, D-92.

**Status: done. The user picked the design (D-91) and granted the permissions for the end-to-end run. Reviews ran on local commits before the push (D-89); merged once CI is green on the final commit.**

All recordings and transcripts here are invented: the end-to-end clip is two `say` voices playing an invented planning call. No real recording or transcript went anywhere.

## What landed
| Area | Now |
|---|---|
| App | `Sources/MeetingCaptureDesktop/`: a SwiftUI app on `MeetingCaptureCore`, option 1 of the mock-ups (D-91). Library sidebar (Today, Earlier, a live row while recording or processing), Record in the toolbar and as a large button, the balanced waveform, a processing screen with one row per step, the report, a Speakers sheet, Settings, and a two-step first run |
| Core facade | `DesktopAPI.swift`: `AppSettings`, `Recorder`, `MeetingProcessor` (stage and progress events), `Library` and `LibraryEntry`, `ModelStore`, `SummaryService`, `LaunchEnvironment`, `ReportNavigation`. The app and the shell both use it, so no core logic lives in the app target |
| Shell | Recording and processing go through the same facade. New main-menu item 6, Library: open a report, transcribe again, write the report again, rename speakers, show in Finder. New Settings item k, Test CLI connection |
| Models | Downloaded on first run, never bundled: size, per-model progress, Cancel, and resume that keeps what was fetched. The cache is the one the terminal uses |
| Permissions | The app has its own identity (`com.meetingcapture.desktop`) with usage strings for Microphone and system audio, a walkthrough with Allow buttons, and Check Again after a trip to System Settings |
| Report view | The same HTML as the terminal in a `WKWebView` with a non-persistent store. The page's CSP allows only its own hashed script; `ReportNavigation` lets only `about:` load, sends clicked http/https links to the browser and refuses everything else, `target=_blank` included |
| Finder launch | `LaunchEnvironment.addUserToolFolders` adds the usual install folders to PATH, so `claude` and `codex` are found when the app opens from Finder |
| Packaging | `scripts/build-app.sh [--install]` makes `.build/MeetingCapture.app` with `packaging/Info.plist`; signed with an Apple Development identity when the Mac has one, else ad-hoc. Distribution would need Developer ID signing and notarization (D-92) |
| Platform | The whole package targets macOS 26 (D-92); `install.sh` stops below 26 |
| Parity | `docs/parity.md` maps every desktop feature to its terminal place; `ParityTests` drives the CLI menus and checks the doc against them |

| Review 1, must-fix | A recording stopped while another job ran was dropped without a word: no processing, and hidden from the library | Jobs wait in a queue and run in turn; the screen says how many are waiting | none: the queue is in the app target, checked by hand |
| Review 2, must-fix | A recording whose job was cancelled or failed vanished from the library until relaunch, because its sidecar's pid was the app's own | `Library.entries(in:busy:)`: this process's sidecars count as unfinished unless the app says it's still working on them | LibraryTests / M5ReviewFindingTests |
| Review 3 | ⌘Q during a recording cut it off with no question | `applicationShouldTerminate` asks; on Quit, the recording is stopped and its files closed first, and the next launch offers it | none: checked by hand |

## Surprises
- **`MicCaptureRestartTests` failed in one `check.sh --unit` run** (7 assertions, Core Audio -10868) while another build and the test writer were running; alone it passed 6 of 6. It uses the real mic, so it seems to need the mic to itself. Not changed.
- **Saving settings from the app writes `llmRoute: subscription`** into `config.json` where it was missing; the value is the same default.

## Still unsure
- The waveform shows the last 6 seconds, not the whole call; D-91 asked for one calm waveform "for the whole call". It reads well in use, but the user hasn't seen it live.
- The app hasn't run on a Mac without an Apple Development identity, where it would be signed ad-hoc and lose its grants on every rebuild.
