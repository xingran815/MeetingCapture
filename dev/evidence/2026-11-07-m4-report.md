## Surprises
- **A test run reached the user's real API profile.** The first test writer ran the binary with `HOME` set to a temp folder, which `NSHomeDirectory` ignores, so three calls with an invented transcript went to the user's DeepSeek profile, and an earlier smoke run added three fake counts to the real usage ledger. The user was told. Config and key files were unchanged. `AppHome` is the fix, and `SummarizeFlagTests` run the binary in a temp home.
- **Claude returns a schema reply only as `structured_output`.** A fake that printed the JSON as text failed with "no structured output". The fakes now emit it the way the CLI does.
- **The first full quality run didn't record which side was A.** The rating table gained an "A was" column; the evidence notes it.
- **The sweep blocks a literal shell path in Swift,** including in tests. The finding tests' two `/bin/bash` lines became `/usr/bin/env bash`.
- **`MicCaptureRestartTests` failed once in the full check** (restart count 0 instead of 2) while the user was playing audio. It drives the real audio engine; the rerun passed. Not flaky code, but a test that shares the Mac's audio can be disturbed.
- **The full check failed twice for reasons outside M4's code.** A CLIRunner timing test took 3.9 s against a 1.2 s limit under 4 workers (0.8 s alone, five times out of five), and the check-modes self-test didn't know `--live`'s new live report step. The second was fixed by a test writer; the first is left as is (see below).

## Assumptions, and why
| Assumption | Why |
|---|---|
| Templates compiled in as text, not an SPM resource bundle (D-82) | `install.sh` copies only the binary, so a bundle would be left behind |
| Report fields beyond the spec's sketch (D-83) | A concept's three parts and a goal's own words had no place in the spec's item fields |
| Concept sources only from the search call, reattached by name (D-84) | So the reviewer can't add a URL from memory |
| `.report.json` beside every report; the HTML date is the run's local time (D-85) | M5's app needs a source to read; the recording's start isn't known for `--summarize-only` |
| API profiles use one model for every step, schema in the prompt, no concept search (D-86) | A profile has one model and no search tool; the subscription CLIs stay the default |
| How many highlights is right (D-88) | Only the user's reads measured it; other transcripts may land elsewhere in the range |

## What's still unsure
- Highlight counts come from the model following a prompt. The code caps them at two per item and drops repeats, but how many items get any is up to the model.
- `testACLIThatExitedIsNotWaitedOnForItsBackgroundChild` has a tight 1.2 s limit and failed once under load. It isn't M4 code. If it fails again, give the limit room.
- The quality run is one run per scenario, on Claude only. A one-point rating difference is within what a second run might change.

- `--live-check` ignores CLI-only (the last low above). Worth sharing one runner factory if it ever runs in a CLI-only script.
