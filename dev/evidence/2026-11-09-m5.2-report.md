## What landed
| Area | Now |
|---|---|
| Groups | `groups.json` in the output folder, keyed by base name: id, name, members, `redactContext` (on by default) and an optional pinned scenario. A report belongs to at most one group. Changes are made under a `flock` on `.groups.json.lock`. A newer or unreadable file is never overwritten. Moving a recording to the Trash takes it out of its group |
| Context | Only reports recorded before this one count (sidecar `createdAt`, then the name's stamp, then the file date), newest first, with a 24,000-character cap and 4,000 characters of notes per report. Allow-listed fields only: title, scenario, date, section titles, item text and detail, the priority mark, keywords, and the user's edits. Notes go in only when that report's switch is on. Transcript, quotes, review changes and notices never go in. Every token shape is stripped from old reports, and each field is folded to one line |
| Redaction | Transcript, notes and context are redacted together in one token space (`redactTogether`). The group's switch can only turn context redaction *off*. With global redaction off, nothing is redacted |
| Steps | Context goes to the sections and review steps, never to classify (D-97). An item may carry a fact that only an earlier report has, marked `source: "earlier"`. The schema allows that only when context was sent, and `cleaned()` drops a stray mark |
| Rendering | HTML shows "From an earlier report: Not said in this recording.", Markdown shows `_(from an earlier report, not said in this recording)_`, and the terminal shows `[earlier report]`. A carried-forward fact keeps its mark in the next report's context |
| Prompts (D-98) | When a recording follows up on something an earlier report has, that earlier fact becomes its own item, marked earlier and never mixed into this call's lines, a few at most. The review keeps such items and doesn't reword them into this call's words |
| Notices | The report names the reports it used and the ones it left out (no report, later, over the cap, gone). It also notes when the group's switch was off, and says the review checked against the earlier reports |
| Terminal | Main menu 7 Groups (rename, redaction switch, pinned scenario, take out, delete); Library › g puts a report in a group; `w` names the group whose context will be used |
| App | More › Group, a Manage Groups… sheet (also in the menu bar), groups listed first in the sidebar |
| Also | `Redactor.safePrefix`: no cut before redaction falls inside a value a rule matches (notes, edits) |

## Surprises
- **The review step undid the point of the milestone.** Told to check against this transcript only (D-94), the frontier review removed every earlier fact as "not in the transcript". Showing it the context, and letting it keep marked earlier items, was the user's call (D-97).
- **Letting the models keep earlier facts wasn't enough on its own.** Run 2 marked nothing and reworded week 1's words into week 2's lines. The prompt had to ask for each earlier fact as its own item, with an example (D-98).
- **A redaction gap since M5.1:** cutting text before redaction can split a value so that no rule matches it.

## Still unsure
- **The live read is one pair of invented calls.** On longer groups, a model may add more earlier items than "a few". The cap and the prompt limit this, but it hasn't been measured.
- An earlier deadline can show up as a to-do with no owner, marked earlier. The user passed it, but some readers may find it noisy.
- Spoken names aren't redacted (as before); the context carries whatever names earlier reports wrote.
