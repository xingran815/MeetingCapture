## What landed
| Area | Now |
|---|---|
| Pre-commit | Secret sweep, then format and lint of the staged text. No build |

## Surprises
- **The auto-mode permission check refused removing the branch block,** as `[Security Weaken]`. Asked, the user chose to keep it (D-62). A spec being committed didn't make that edit acceptable to the check, so a later edit that removes a guard may need the same conversation.
- **`| grep -q` under `pipefail` can read a match as no match:** it exits at the first hit, and the command still printing gets SIGPIPE. My new self-test failed this way, and the older `expect` helper had the same hidden flake. Now in `CLAUDE.md`.
- **A worktree appeared during this milestone:** `.claude/worktrees/m3.2-echo`, locked, on the `main` from before this PR, branch `worktree-m3.2-echo`, no commits of its own. This session didn't make it, and left it alone.

## Still unsure
- Why the builds still take a minute on an exact hit. Pinning file times could help, but a wrong pin could reuse stale objects and give a false green, so it wasn't tried.
- Whether `main`'s cache saves more than a branch's. M3.2's first PR is the first test.
- The first `main.yml` run is the merge itself; `ci.sh main` has only run against stubs.

## What M3.2 needs to know
- The new hooks and review rules apply from now on. Run `scripts/check.sh --full` before the final push: the verifier reads the record instead of rerunning it, and a dirty tree or a moved HEAD spoils it.
- Pre-commit no longer builds, so a commit may not compile until pre-push or CI says so.
- Check M3.2's first PR logs for `Cache hit for restore-key: swiftbuild-main-`, which finishes proving Done-when 6.
- If `.claude/worktrees/m3.2-echo` is the M3.2 start, it needs this merge first. CLAUDE.md's rule is no worktrees, and D-59 lists only subagents as M3.2's exception.
