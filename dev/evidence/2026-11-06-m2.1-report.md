## Surprises
- **Stale events:** Auto-fix reported failures on commits already replaced, twice. Compare the head first.
- **No event on green:** Auto-fix only speaks up about problems, so a passing run needs someone to look.
- **A public list of protected commit ids would have pointed at the old email,** because GitHub still serves those pre-rewrite commits. Hashes avoid that (D-34).
- **Zsh reads `echo ==` as a file lookup** and stops the command. Edits before it had already landed, so check state before re-running.
- **Runners queue:** some jobs waited about 5 minutes for a macOS runner on the first run.

## Still unsure
- **No `push` to `main` CI run has been seen yet.** The first merge is the first test of the `github.event.before` range. It fails closed if that value is unusable.
- **Runner minutes:** the runs succeeded on the standard runner, but I didn't confirm from billing that they're free for this repo.
- **The `whisperkit` resolution failure** didn't recur in any CI run, so its cause stays unknown.
- **Tokenizer:** CI's model is pinned, but WhisperKit downloads its tokenizer unpinned.
- **The protected list is a snapshot** of the local branch; new commits there aren't in it. The pre-push hook stays the live check.
- **Lint tools on CI** come from Homebrew unpinned, so a new `shellcheck` could turn CI red with no code change.
- **Open for the owner:** `Package.swift` says macOS 14, while the spec says macOS 26.
