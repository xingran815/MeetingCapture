## Known lows left
D-53, D-55, D-57 and D-60. The two that matter next are in the M3.2 spec: the mic start gate can leave very short mic gaps, and it could put the echo ahead of the reference, where Speex removes almost nothing.

## Surprises
- **The real room was far harder than the invented one.** 34-41 dB on invented speech became about 10-20 dB in a real room. Only the user's ears found this.
- **The first fix found a real bug and still didn't solve the problem.** The startup lag was real, but the speakers reach the mic at full strength.
- **Three real calls can't compare cancellers,** because they had already been through one. Only a recording with the canceller off holds raw echo.
- **Level can't separate soft speech from steady noise.** Two rounds of thresholds failed before the design changed to flag, not drop.
- **A commit hook runs inside the push and commit too,** so a "background" commit can run for minutes while the user records. Long checks and real-time recording shouldn't overlap.
- **Zsh reads `echo ======` as a file lookup** and stops the command, again.

## Still unsure
- **Label quality on a separated track.** `m3-check3` had a `Speaker 2`, and the user didn't say whether a second person spoke. M3.2's Done-when 5 covers it.
- **The noise thresholds on a real noise-only track.** The note never appeared on a real call.
- **A real crash** was never tested on real audio, and the shell's recovery path has no E2E test.
- **`logProbThreshold` off** may still skip a window; there were no gaps over 13 s on the real calls, but they were short.
- **macOS 14** is untested. Only macOS 26 has run this (D-51).
- **Whether the mic ever leads the reference on real hardware** is unknown, and M3.2 should measure it across several starts.
