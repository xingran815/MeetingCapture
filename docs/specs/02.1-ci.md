# M2.1 — Continuous integration

**Goal:** every PR and every push to `main` proves, on a clean machine, what the local hooks prove on this Mac, plus the checks a hook can't do.

**Starts after M2 merges.** Branch `m2.1-ci`. Add the `dev/PLAN.md` row and the decision lines when it starts, because M2 is editing those files now.

## Why CI, when hooks exist
Hooks run only on a machine where `scripts/setup.sh` ran, and they can be skipped. CI runs from a fresh checkout whatever happened locally, so it catches "works on my machine", missing files, and anything that got past a hook.

## Rules for the workflows
| Rule | Because |
|---|---|
| Workflows call `scripts/*`; no logic in YAML | Local and CI must give the same answer. |
| Run on `pull_request` to `main` and `push` to `main` | Covers the PR and what actually landed. |
| `macos-26` standard runner, never `-large` or `-xlarge` | Matches the deployment target. Larger runners are likely paid. |
| `permissions: contents: read`, no repo secrets, no `pull_request_target` | The repo is public; a workflow can't leak what it doesn't have. |
| Actions pinned by full SHA | A moved tag can't run new code here. |
| `timeout-minutes` on every job, cancel older runs on the same branch | A hang can't burn the budget. |
| Budget: under 15 min for the required jobs | Otherwise it stops being looked at. |
| Check out the PR head SHA with `fetch-depth: 0`, not GitHub's merge ref | GitHub's merge commit carries its own identity and would trip the identity sweep. The sweeps also need history. |

Confirm on the first run that the runner minutes are free for this public repo. Unsure until then.

## Required jobs
| Job | Runs | Fails when |
|---|---|---|
| **Build and unit tests** | `swift build`, `swift build -c release`, `swift test` with fake CLIs on `PATH`, then the no-fake-CLI guard | Compile error, failed test, or a test run that could reach a real model. Release is what `install.sh` ships, and debug passing doesn't prove it. |
| **Secret and leak scan** | `scripts/test-sweeps.sh`, `sweep.sh --tree`, `sweep.sh --outgoing` over the PR's commits | The sweeps stop catching seeded leaks, or a key, email or sensitive file is present. |
| **Commit identity** | Author and committer of each PR commit are noreply; no AI attribution; `feature/coding-interview` isn't on the remote and no pushed commit descends from it | A commit made where the hooks didn't run, or the branch rule was broken. |
| **Lint and format** | `swift format lint --strict` with a checked-in `.swift-format`, excluding `Sources/Speexdsp`; `shellcheck` on `scripts/` and `.githooks/`; `actionlint` on the workflows | Unformatted Swift, a shell bug, or a broken workflow. |
| **Dependencies** | `swift package resolve`, then `Package.resolved` must be unchanged | The lockfile and manifest disagree. |
| **Fresh clone** | `scripts/setup.sh` on the clean checkout installs the hooks | Setup depends on something only this Mac has. |
| **Short-audio E2E** | `scripts/e2e.sh` with a cached small Whisper model | Transcription breaks. **On CI, a skip counts as a failure**, unless the job is deliberately moved to nightly (below). |

### Things to settle while building
- **Flaky dependency resolution:** on 2026-11-06 a fresh worktree's first `swift build` failed with "no versions of 'whisperkit' match", and a `swift package resolve` minutes later worked with no change. Cause unknown; another session was building at the time and SwiftPM's cache is shared, which is only a guess. If it shows up on the runner, find the cause before adding a retry.
- **Format baseline:** `swift format lint` printed 136 lines on today's code. One commit does only the reformat, before the lint job turns on. Add the lint to `scripts/check.sh` so local and CI match.
- **`shellcheck` and `actionlint` locally:** neither is installed here, and installing needs a yes. They run in CI; `check.sh` runs them only if present and says when it skipped them.
- **E2E on the runner:** `e2e.sh` skips silently without the model and depends on `say`. Add a `CI` branch that fails instead of skipping. Cache the model with `actions/cache`. If the runner has no usable `say` voice, or the download makes the job too slow or flaky, move E2E to nightly and say so here.

## Not in CI, on purpose
| Left out | Because |
|---|---|
| Real `claude` or `codex` calls, `--live`, quality comparisons | Needs a login, spends usage, and a transcript has no business on a hosted runner. |
| Recording (Screen Recording, Microphone permissions) | The runner can't grant them. Stays a manual check. |
| Listening checks | Needs ears. |
| Coverage percentage gate | A number to chase; findings-become-tests does the real work. |
| Older macOS matrix | Deployment target is macOS 26, for one user. |

## Merging
- **`gh pr checks` must be green before the local ff-only merge.** This becomes a row in the `CLAUDE.md` rules. The merge stays local (`git merge --ff-only`, then push), never GitHub's button.
- **Branch protection is a 👤 question, not a default.** Required status checks can refuse a direct push to `main`, and bypassing that needs rulesets, so it may break the local merge flow. Test it on a throwaway branch first, then ask. Blocking force-push and deletion on `main` is safe to propose on its own.
- Repo settings (protection, Dependabot security updates) change only after the user says yes.

- [ ] **Each gate is seen red for a real reason, without `--no-verify`:** a badly formatted file fails lint on the PR and is then fixed; `test-sweeps.sh` proves the sweeps catch seeded leaks in CI; the identity job is exercised with `scripts/` fixtures, because a bad commit must not reach the public repo.
- [ ] E2E on CI really transcribed: the log shows the fixture's words, or E2E is nightly and that run is linked.
