# M5.1: the report as a notebook

**Goal:** a report is something the user keeps and shapes: rename it, write notes in it, edit it, delete it. Starts after M5 merges. Decisions: D-93.

## Where the user's layer lives
`ReportFiles.write` re-encodes the whole `.report.json` on every run, so nothing of the user's goes there. It lives beside it and is merged at render time, so a re-run can't overwrite it:

| File | Holds |
|---|---|
| `<base>.edits.json` | `userTitle`, content overrides, the "send notes to the LLM" switch |
| `<base>.notes.md` | The user's notes, as written |

`LibraryEntry.reportHTML()`, `ReportRenderer` and the terminal's `ReportConsole` merge `edits.json` when they render; `userTitle` shows in the sidebar, window title, HTML and terminal.

## Features
| Feature | Where | Design |
|---|---|---|
| Rename the title | Desktop and terminal | `userTitle` in `edits.json`; the model's `topic` is kept |
| Notes | Desktop and terminal | `<base>.notes.md`, shown in the report page. In the app it's edited in place; the terminal opens it in `$EDITOR` (or `open -t`). **Not sent to the LLM by default**; when the user turns it on, notes go through the same redaction as the transcript |
| Edit content | **Desktop only** | Each override stores the original text it replaced. On render it applies only if that original still matches; otherwise the page says "N edits no longer match" and the user keeps or drops them. "Write the report again" asks whether to keep the edits, with that meaning |
| Delete a recording | Desktop and terminal | Moves to the Trash, after a confirm, the files the sidecar lists: `audioFiles`, the new `reportFiles`, the fixed-name files (`.txt`, `.md`, `.report.json`, `.edits.json`, `.notes.md`), then **the sidecar last**, so a crash midway leaves a sidecar that lists what's left. Never by name match (D-44). Nothing is deleted for good |

## Changes to make this safe
- **`reportFiles` in the sidecar.** Each report write makes a new dated HTML (`ReportFileName.freeURL`), and nothing records it today. `ReportFiles.write` appends the HTML's name to a new sidecar field `reportFiles`. Reports written before M5.1 have no record: delete leaves their HTML and says so; it never guesses.
- **Every report has a sidecar.** `ReportFiles.write` makes a minimal sidecar when there is none (a `--summarize-only` on a loose `.txt`), so every library entry has a file list.
- **Stale HTML.** After an edit or rename, the HTML files in `reportFiles` are re-rendered in place, so the terminal's Open and Finder show the edited report.
- **Trash in tests.** The remover is injectable, so tests never touch the real Trash.

## Parity
`docs/parity.md` gains rename, notes and delete on both sides. Editing content is a documented exception: desktop only.

## Done when
- [ ] Rename, notes and delete work in the app and the terminal; editing works in the app.
- [ ] Delete moves only the listed files to the Trash, sidecar last; a test proves a similarly named file survives, and an old report's unrecorded HTML is left with a message.
- [ ] A re-run keeps the title and notes, and keeps or drops edits as chosen; an edit whose original changed is reported, not silently applied.
- [ ] Edited text renders escaped; a test puts script tags in an edit, a title and the notes.
- [ ] Parity checklist and verifier pass, with screenshots.
